# Teacher and harness evaluation protocol

Use `just dashboard` to inspect recorded teacher, student, gate, campaign and utility results locally. See [the results dashboard](dashboard.md) for setup, artifact discovery and missing-result behavior.

## Study status and roles

This protocol specifies a future study. Its acceptance targets are proposals, not measured outcomes. Historical v3 A1/A2 campaigns and the v4 reordering probes are development evidence; they have already been inspected and cannot be used as a locked final test. Keep frozen artifacts read-only. Freeze separate source families for representation fitting, reference fitting, score calibration, policy development and locked final test. Split news by publisher, period and topic where available, QA by document, math by problem family, and coding by problem lineage. Screen near duplicates across roles. Record the source manifests, selection rules, versions, seeds and limitations before calibration. The workload and calibration implementation is separate work and must be integrated before claiming these checks ran.

## Baselines and campaign design

The intended baseline panel is allow, full MMD, instantaneous MMD, request quota, rate limit and request-plus-output-token quota. The last baseline requires the separate accounting implementation; declaring it here does not enable it. Use fresh account state per condition and the same frozen schedule, deadline and declared resources. Compare cap enforcement with detector escalation separately. Replay is policy-only and cannot establish delivered answers or solved challenges. L1 alert can serve traffic; report L1, L2, L3 and L4 separately and distinguish first alert, restriction and refusal.

Freeze the original A1-A7 attack schedules using `uv run distill gateway schedule --help`, including broad extraction, topic ordering, independent-source and cover strategies, account splitting and rotation as specified by each schedule. Include adaptive reordering, low-and-slow pacing, answer-only requests, deduplication, replay of legitimate sessions, selective retries and budget-aware account rotation. Add paraphrase, batching, verifier filtering and alternative-teacher mixing when available. Charge online calls, proof attempts, output tokens, money and offline work consistently. Fixed-pool reuse and acquisition of new examples are different budgets. The default 6,000 HTTP-attempt budget includes failures and proof redemption; an account horizon can impose a separate 10,000-attempt cap.

The default A1-A7 requests and manifests remain frozen for existing seeds. Opt-in schedule flags are `--topic-sorted`, `--deduplicate`, `--answer-only`, and `--per-account-limit N`. The inventory manifest and execution contract record these variants. Topic ordering preserves the selected prompt set and groups domains into blocks, with eight deterministic farthest-first lexical token-embedding clusters per domain. This implements the order-only attack pattern from the v4 audit; it does not reproduce the audit's fitted embedding clusters or establish the same evasion rate. Deduplication removes exact message sequences after answer-only conversion and whitespace normalization within the selected inventory, retaining the first source identity. It may reduce the number of queries without replenishing the inventory. Answer-only mode replaces only the frozen GSM8K reasoning suffix, retains the `####` numeric format, and leaves unknown templates unchanged. AG News and SQuAD already request answer-only outputs. Declare pacing with `--interval-seconds`; low-and-slow A4 remains the frozen A1 prompt order at that interval. Legitimate-session replay and selective retries are collection options rather than schedule flags; see [adaptive collection options](#adaptive-collection-options).

A8 freezes the complete attacker candidate pools and their hashes with `uv run distill gateway schedule --attack A8 --budget 6000 --round-size 16 --output CAMPAIGN`. Execute with `uv run distill gateway collect --input-dir CAMPAIGN --output RUN --policy POLICY` and the usual teacher credentials and review identifier. `requests.jsonl` is a candidate inventory for A8, not a precomputed query sequence; its `planned_queries` is null and `domain_allocation` is decided online. Do not use the candidate inventory as an executed detector replay. A8 selects a batch, collects it, then reselects using released examples and HTTP-visible refusals, challenges, failures and response latency. Its CPU selector uses normalized sparse token embeddings, greedy cosine novelty relative to acquired prompt coverage, within-batch diversity, and a domain penalty for observed unsuccessful requests and waiting time. It requires no model download or GPU. This is a coverage heuristic, not evidence of student learning or live attack effectiveness. A8 cannot combine online ordering with `--topic-sorted`.

The Python `collect_gateway` API accepts an optional `uncertainty_hook(candidates, released_ledger)` returning finite uncertainty scores keyed by candidate request ID. Supply a stable `uncertainty_hook_id` identifying the hook code, model checkpoint and training configuration; the identity enters the execution contract. The hook can update a student from released responses between rounds. No student is trained by default. The selector never receives the detector decision sidecar or hidden policy state. Every `selection_round` event records selected IDs, combined scores, raw uncertainty scores, cumulative observable feedback, released example IDs, attempts spent and the contract hash. Together with the frozen candidates, selector version, seed and response ledger, these records allow selection replay without querying the teacher or rerunning student training. HTTP attempt and outcome events remain the source of actual submission and release accounting, since a budget or deadline can stop a selected batch partway through.

`--per-account-limit N` derives rotation accounts from the campaign budget and enforces the declared cap at the HTTP submission boundary. Queries, proof redemptions and failures all spend both the account limit and the shared campaign budget. The next query rotates once the current account has spent its allowance; a proof that would exceed its account limit is abandoned. Rotation executes sequentially, keeps the global deadline and pacing, and never replenishes the campaign allowance. `--accounts` cannot be combined with this derived rotation count. Supply separate actual credentials for these accounts when evaluating Sybil behavior. A shared default token only tests local bookkeeping and does not establish independent server-side identities. A8 and rotation retain the existing consecutive-service-failure stop. Interrupted runs require a fresh output directory and cannot silently reset spent allowance.

The benign suite should cover casual users, specialists, broad researchers, batch evaluation, repetitive labeling, iterative coding, long-document QA, shared enterprise keys and nighttime automation. Hold out organizations and source families as well as accounts. Include all horizons and scored horizons, new and established accounts, deadlines, correct task completion, challenge abandonment, recovery, latency and organization-level impact. Demonstrate that the undefended teacher has enough capacity for the legitimate workload before measuring utility. Overload is a separate experiment. The workload worker owns implementation of profiles, source manifests and calibration gates.

## Prepare and deploy

1. Enter `devenv shell`, configure `.env` from `.env.example`, and run `just setup`.
2. Serve an OpenAI-compatible teacher. For the historical teacher, install vLLM separately and run `vllm serve Qwen/Qwen3.5-9B --revision c202236235762e1c871ad0ccb60c8ee5ba337b9a --host 127.0.0.1 --port 8001 --language-model-only --reasoning-parser qwen3`. Reasoning is on by default; see [reasoning withholding](harness.md#reasoning-withholding). Historical readings used `--default-chat-template-kwargs '{"enable_thinking": false}'` and `distill gateway collect --no-thinking`; reproduce them that way. Select quantization and hardware settings appropriate to the host. On a host too small for vLLM, `just teacher-gguf` serves a quantized GGUF through `llama-server` on the same upstream port, using the Vulkan build from `devenv.nix`. Its settings are `TEACHER_GGUF`, `TEACHER_GGUF_CONTEXT`, `TEACHER_GGUF_SLOTS`, `TEACHER_GGUF_GPU_LAYERS` and `TEACHER_GGUF_DEVICE`, plus `TEACHER_GGUF_REASONING` (default `on`) and the reasoning budget `TEACHER_REASONING_BUDGET_TOKENS`. Each slot holds the prompt, that budget and the answer cap, so raise `TEACHER_GGUF_CONTEXT` when the default 8,192 split over two slots is too small. The device defaults to `Vulkan0`, because `llama-server` otherwise spreads across every GPU it finds; `llama-server --list-devices` shows the numbering. A GGUF teacher is a different model and serving stack from the historical one, so record its file hash in `TEACHER_MODEL_REVISION`, set `TEACHER_TERMS_REVIEW_ID` (without it the teacher API answers every request with 503), set `CONCURRENCY` to at most its slot count, re-pass the headroom gate and do not compare its results directly with other teachers.
3. Run `just teacher`, then verify its health and authenticated generation. Set the teacher review identifier and credentials as needed.
4. Build each domain pool with `uv run --extra eval distill tasks build --task ag_news`, and repeat for `squad`, `gsm8k`, and `coding`. Dataset downloads and the coding sandbox have their own resource requirements. Use pinned dataset revisions and keep source groups disjoint. Check that each role covers the intended topics: the benign generators select prompts by category deficit against each domain pool, then group specialist account streams into topic-ordered blocks. The role manifest records per-domain pool and used category counts, topic coverage and maximum share deviation; require each category share to be within 3 percentage points of its pool. Coverage uses distinct prompts so repetition does not inflate it. Do not treat a larger pool alone as evidence of representative traffic.
	AG News, SQuAD, and GSM8K use `data/news`, `data/question_answering`, and `data/math` by default. Their task identifiers remain `ag_news`, `squad`, and `gsm8k` in commands and request records. Use a separate `--output-dir` for builds with different seeds to avoid overwriting an existing pool, and pass its parent with `--tasks-dir` when generating schedules. Pools are built locally and are not committed; `data/` is ignored.
	Each build seals its attacker source groups into two disjoint partitions under `attacker-partition-v1`: an exploratory `attacker.jsonl` and a confirmatory `attacker-confirmatory.jsonl`, each holding about half of the groups. The manifest's `attacker_partitions` records the files and their prompt and group counts. `distill gateway schedule` reads the exploratory partition by default. Use it for development campaigns, detector selection, reordering probes and learning curves. Pass `--partition confirmatory` only for a preregistered evaluation, and query it once. The schedule manifest records which partition it drew from. The v4 audit showed why this separation is needed: the v3 A1 prompts were inspected and reordered while variants were developed, so they cannot also count as an untouched test. Schedules refuse builds without partitions; rebuild those. A partition seal prevents prompt reuse only. It does not hide the prompts from anyone who reads the files. Each partition holds fewer prompts than the whole pool. At seed 42, GSM8K's partitions hold 1,697 exploratory and 1,692 confirmatory prompts.
	Schedules split the extraction budget evenly across domains. The default budget of 6,000 attempts gives 1,500 prompts per domain. This matches the v3 A1 campaign and fits both GSM8K partitions, so exploratory and confirmatory campaigns stay alike. An even split over the four domains fits at most about 6,768 prompts. A larger budget fails and names the binding pool rather than skewing the mix. Skewing would confound detection, because the pooled MMD reference is a fixed domain mixture and a pooled test responds to mix differences as well as to extraction. A3 spends its default 50% cover share of the budget on cover, so at 6,000 attempts it sends 3,000 extraction prompts, 750 per domain. To collect more GSM8K, enlarge its source and rebuild and recalibrate, rather than changing the mix. An uneven mix through the `campaign_schedule` allocation argument is a separate experimental condition and should be reported as one.
5. Generate separate benign fitting, score-calibration, policy-calibration, and held-out test schedules with `uv run distill gateway benign --help`. Use `distill gateway detector-input` on each schedule. These files contain domain-tagged detector text, identities, and source groups. Check the source separation yourself before calibration. The gateway serializes the tagged turn according to its domain.
6. Run `uv run --extra embed harness calibrate --fitting FIT.jsonl --score-calibration SCORE.jsonl --policy-calibration POLICY.jsonl --output-dir artifacts/harness --task gateway`. Inspect the calibration counts and thresholds. Minimum empirical resolution is not proof of population false-positive control. A new configuration or workload requires a fresh calibration and output directory.
7. Configure account keys and gateway caps in `.env`, then start `just harness`. Use independent credentials and account identities for the experiment. See [harness settings and behavior](harness.md).

## Opt-in source-family workload and recalibration

The default `gateway-clients-v3` workload now balances category selection before ordering account topic blocks. `gateway-clients-v5` also balances selection before grouping specialist and document streams, rather than pinning a category during selection. These changes alter generated inventories. Existing output directories are rejected; preserve frozen inventories and generate into a new directory, then recalibrate. For a new study, use `gateway-clients-v5` with `distill gateway profile-build --help`. It samples by topic deficit and includes broad generalists, specialists, batch evaluation, repetitive labeling, iterative coding, long-document QA, shared enterprise keys and nighttime automation. Synthetic profiles are not observations of actual customers. A separate account is created for each requested profile horizon. The default 300 per profile gives a one-sided 95% zero-event bound of about 1% only if horizons are independent; source-family separation helps but does not prove independence. Smaller fixtures establish plumbing, not that bound.

Prepare an audited JSONL of `distillation.role_workflow.SourceItem` records with a prompt, benchmark reference, `family`, `family_kind`, and a specific `provenance` citation for each item. The required kinds are `document_title` for SQuAD, `problem_lineage` for coding, `problem_family` for GSM8K, and `publisher_topic_period` for AG News. The family value must identify the corresponding family within its corpus. Existing task builds do not establish all of these fields: in particular, a text hash is not evidence of a GSM8K family or news publisher. Obtain and audit suitable source metadata or use different sources. Unknown provenance fails; the builder cannot verify the truth of supplied assertions. Do not claim disjointness beyond the source evidence.

Run `devenv shell -- uv run --extra embed bash scripts/recalibrate-profiles.sh SOURCE.jsonl NEW_OUTPUT_DIR 300` on a machine with the encoder dependencies and suitable hardware. The script freezes representation-fit, reference-fit, score-calibration, policy-development, and locked-test families, creates profile schedules and detector inputs, validates them, calibrates using the latter three fitting roles, and writes an adequacy report. Representation fit is reserved for fitting a representation; the existing pinned BGE encoder is not fitted by this script. The locked test is never used to fit or select a policy. Validation checks hashes, family and account separation, category and profile coverage, and cross-role five-word-shingle near duplicates. Candidate search excludes very common shingles and can miss paraphrases, so review provenance and leakage separately. It rejects insufficient capacity, missing domains or topics, shared families, time spans over one day, and skew; lower the count only for plumbing fixtures. Retain the frozen input, role manifest, validation report, calibration and adequacy output together. The script stops at a failed gate and never contacts the teacher.

The v3 A1/A2 runs and v4 reordering probes are development evidence only; they are not locked final tests. A new workload, source allocation, detector serialization, or policy requires a fresh output directory and recalibration. Do not reinterpret prior readings as results for this workload.

## Execute and report

After preparing the deployment, freeze schedules and execute them with `uv run distill gateway collect --help`. For the default four-domain balanced allocation, A1, A2, A4, A5, A6 and A7 require 1,500 distinct eligible prompts per domain at the default 6,000-attempt budget, a quarter of the budget each. A3 divides the budget between independent-source extraction and cover pools according to `--cover-share`. Build the selected pools first; schedule generation rejects a pool that is too small. The `external` command prepares independent-source pools for A3 and A7. Use fresh output directories and retain contracts, schedules, event logs and response ledgers. Do not infer a delivered answer from admission or a scheduled prompt.

`collect` requires `--policy` to declare the policy the gateway serves for the arm: `mmd`, `quota`, `rate`, `allow`, or `none` for a direct teacher. When the gateway's `/healthz` reports a different policy, `collect` refuses. An `mmd` arm must pass a detectability gate before any request is sent. The gate replays the frozen schedule offline through the `--calibration` the gateway serves, using the same detector serialization and policy code and the same time order and attempt budget as `collect`. It also replays the held-out benign accounts from `--benign-test`. Declare the study's MMD arms with `--gate-accumulator` (default `paper` and `instantaneous`). An arm escalates the attacker when the attacker's highest level is above L0 and fewer than the L1 target share of the scored benign horizons reach that level. When no declared arm does, `collect` prints each arm's attacker peak and exits without creating the run directory. It restores the pre-campaign check whose absence let the v3 protected A1 campaigns run (finding F3 in [the v4 analysis](../readings/v4/analysis/REPORT.md)). `--allow-undetected` runs the arm anyway. The contract, `campaign.json` and `detectability.json` then record the override and the reading `quota comparison`; report such a run as a quota comparison, not a detection result.

For `--benign-test`, pass the detector input of a held-out benign schedule that took no part in calibration. For `gateway-clients-v3` this is the `benign_test` role. A file whose content matches a calibration role is rejected. For `gateway-clients-v5`, prefer a separate held-out benign set to the locked test. If the locked test is used, report that the gate inspected it. The gate runs on CPU with the calibration's encoder and reuses embeddings from `--embedding-cache` (default `artifacts/embedding-cache`), which must lie outside the calibration, the schedule and the run directory. Repeat `--embedding-archive` to reuse existing embeddings read-only, such as the v4 offline audit's `detector.npz` of detector-text SHA-256 keys and vectors. An archive records no encoder identity, so use only archives produced by the calibration's encoder. It writes only to the cache and, after it passes, to the new run directory. The gate is a go/no-go check, not a power estimate. Never use it to tune thresholds or select a policy. It replays calibrated thresholds with graduated actions under the legacy policy version; arms served with `ville` thresholds, `direct` actions or `verify-risk-v2` are gated under different settings than they run. The `/healthz` check confirms only the policy name, not the served calibration or accumulator; `detectability.json` records the calibration hash that the gateway logs with each decision, so the match can be checked afterwards. Passing it is not evidence of effectiveness: it uses a single frozen schedule and offline replay, without challenges, solved proofs, deadlines or live load.

Every campaign has one summary, `distillation.campaign_summary`. `campaign.json` stores it, `uv run distill gateway evaluation-report --events RUN/campaign.events.jsonl` prints it, and `campaign-timing.json` and the results index read it. `attempts` counts every HTTP submission and splits into `query_attempts` and `proof_attempts`. Outcome counts keep `failed`, a failure before the deadline, apart from `deadline`, a failure after the campaign's time ran out. Each level records the manuscript's `J`, the first attempt index whose account reached it, its decision time, account and domain, and `Q`, the received responses completed strictly before that time, with `Q_by_domain` adding released tokens. An unreached level is censored. Admission and cancellation are not in the event log and stay null. Missing usage makes the total released-token count null; the known subtotal and the number of unknown usages are reported beside it. `attribution_complete` requires a policy event for every query that came back with a harness decision; `unattributed_queries` counts queries with no policy event, such as transport failures, so missing intervention times are not proof of absence. The current policy event omits release time, so delayed serve restrictions cannot be timed. `campaign-timing.json` adds each account's first challenge, block and observed stop, deliveries per window, and latency distributions. A `campaign.json` written before this summary is translated on reading, with fields it never recorded left null. Completed and interrupted campaigns require separate labels. Report time to intervention and acquisition across all accounts through the deadline, including data released after an alert.

### Measuring a campaign arm

Passing `--restriction-strategy` to `collect` opts into attributed collection and a `gateway-execution-v3` contract. Without it, contracts, events, summaries and 429 handling are unchanged, so existing arms and run directories behave as before. The strategy is part of the contract. `give_up` drops a restricted prompt and moves to the next scheduled one. `wait_and_retry` waits the server's retry delay and submits the prompt again, up to `--restriction-retries` times per prompt; a response with no numeric delay gives up on that prompt. Every rejected submission spends the shared HTTP allowance, waits spend campaign time and are logged as `restriction_wait`, and each abandoned prompt is logged as `restriction_give_up`. A retry is a fresh query with a new root. It does not re-send a held proof, although the API would accept one after the cooldown, so that attacker option is not measured yet.

A 429 with a harness decision header or a known harness code, or a 502 with code `output_withheld`, becomes outcome `restricted`, carrying its kind (`campaign`, `entitlement`, `rate`, `output` or `unknown`), its code, the decision and retry timing. It resets the consecutive-failure count, as a policy refusal does, and cannot end a campaign as `service_failures`. A 429 with neither signal stays `failed`, because it may come from an upstream service. A stop caused by client abandonment therefore no longer reads as sustained protection, and ten quick throttles no longer end the run.

The merge imports `campaign_throttle` rows as their own events, and retains campaign evidence, `campaign_override`, reason, entitlement, policy revision and server time on decisions. The summary becomes `campaign-summary-v2`, adding `restricted`, `restrictions_by_kind`, `restrictions_by_cause`, `restriction_wait_seconds`, `restriction_give_ups`, `first_entitlement_restriction_seconds`, `ambiguous_policy_rows` and a `campaign` block. Levels remain detector levels. An observe alert moves `first_alert_seconds` and never reaches L1, and an early entitlement refusal never reaches L4. `measure_utility(attribute_restrictions=True)` likewise records a `restricted` status and cause instead of `error`, and joins the utility contract. Benign clients do not retry, and utility scores are unaffected.

`--campaign-config` with `--campaign-mode` binds the configuration's file hash, canonical digest, mode and session version, and the base policy, into the contract. The file is copied into the campaign directory. The API does not report its policy revision before a run, so the revision is observed afterwards. The collector freezes the decision log as `decisions.snapshot.jsonl` and records a `policy_binding` in `campaign.json`. The status is `bound` for one revision with evidence from the declared configuration, `unknown` when the log has no revision, and `conflict` for several revisions, undeclared evidence, unparsable rows or a throttle in an arm that did not declare one. A finished run is never discarded over this: the status is recorded and `collect` exits nonzero. Resume and export then refuse anything but `bound`.

`scripts/study.sh` has two opt-in arms, `campaign-observe` and `campaign-throttle`, selected through `ARMS`; the default `ARMS` does not include them. Both serve base policy `allow` through the product launcher, with `--state-db` inside the arm's fresh directory:

```bash
ARMS="allow campaign-observe campaign-throttle" \
CAMPAIGN_OBSERVE_CONFIG=path/observe.json CAMPAIGN_THROTTLE_CONFIG=path/throttle.json \
CAMPAIGN_RESTRICTION_STRATEGY=wait_and_retry CAMPAIGN_RESTRICTION_RETRIES=3 \
HARNESS_CAMPAIGN_ALLOW_UNQUALIFIED_ENFORCEMENT=true just study RUN_ID
```

### Unprotected reading and student

After every protected arm and utility run, `scripts/study.sh` takes one unprotected reading: the `UNPROTECTED_ATTACK` schedule (default `A6`, which must be in `ATTACKS`) served under policy `allow` with no intervention, written to `campaigns/A6/unprotected/`. It then stops its own teacher and vLLM, exports the reading's chronological checkpoints, plans the GSM8K student, trains it and benchmarks it with `distill checkpoints execute` under the shared `trace-gpu.lock`, and writes the summary. Student files go to `artifacts/students/RUN_ID/unprotected/`, outside the run directory, so the readings export never copies weights.

The accuracy target must be declared before the run, as for any checkpoint student: set `STUDENT_TARGET_ACCURACY` in (0, 1], or set `STUDENT_TRAIN=0` to take the reading without training. `UNPROTECTED=0` skips both. `STUDENT_SUITE` (default `data/math/development-suite.json`) and `STUDENT_SEED` (default 42) select the suite and seed. The earlier v7 unprotected reading was not collected this way: it is the A6 quota run, whose quota never fired.

The script refuses a missing config file, strategy or retry count, and a throttle arm without `HARNESS_CAMPAIGN_ALLOW_UNQUALIFIED_ENFORCEMENT=true`, before any preparation. It refuses a config whose mode differs from the arm before any service starts. The observe arm sets that variable to false explicitly, so a product `.env` cannot turn observation into enforcement. These arms make the detectors measurable. They have not been run, so no detection, prevention or economic result follows from them. The study script still stops at collection, utility and reporting; checkpoint students remain a separate explicit step.

Campaign rows also carry `restricted`, `restrictions_campaign`, `restrictions_entitlement`, `restrictions_rate`, `restrictions_output`, `restriction_wait_seconds`, `restriction_give_ups`, `first_entitlement_restriction_seconds`, `policy_binding`, `campaign_digest`, `output_receipts` and `output_receipt_mismatches`. They are empty for runs without attribution, where they are unknown rather than zero. Older rows load with them empty, and the header gains them on the next export. Exporting a `just study` run with `just reading RUN_ID` also replaces that run's rows in `readings/index.tsv`, a plain TSV kept outside Git LFS. It has one row per campaign arm and per benign utility arm, keyed by run, kind, attack, arm and `stratum`, so gate-refused, interrupted and unrun arms keep a row and a `status`. Each row records the reading, commit, policy, accumulator, seed, budget, attacker partition and the derived `study` (development for exploratory, confirmatory otherwise), the detectability `reading_label`, the contract, schedule and calibration SHA-256, and the first `policy_revision` in the arm's decision log. Campaign counts, `J`, `Q` and intervention times come from the canonical campaign summary, left empty for an unreached level; utility rows record served counts, completion, quality and p95 latency, pooled in the `all` stratum and again for each domain, profile and client type, such as `client_type=specialist`, so a group that loses service is visible when the pooled average is not. Comparisons report the per-stratum utility of each arm beside the pooled value. Campaign rows also record their ledger's SHA-256, which links them to the students trained on it. An empty cell is unknown, not zero. Empty level cells mean an unreached level only when `attribution_complete` is true; an interrupted campaign whose decisions were never merged into its event log, such as the v3 A2 arm, has `unattributed_queries` instead. Export refuses a contract hash that already belongs to another row. `just backfill` rebuilds the rows of the frozen v3 study and the v4 audit's undefended v2 evidence. They are labelled `backfill:` in `run_id`, have no commit and count as development evidence; fields those files never recorded, such as v3 policy revisions, stay empty, and the v2 counts come from their legacy `campaign.json`. The index lists what was run and where its evidence is; it does not replace the reading's limitations or interpretation.

For benign profiles, report escalation, restriction and deadline completion with known and total denominators. Also report correct task completion, p50/p95/p99 latency, challenge abandonment, review and restoration burden, and compute. Missing task outcomes remain unknown. The small authored `distill traffic` suite is a synthetic development check, not representative benign evidence.

For a small authored traffic suite, run `distill traffic freeze --output data/traffic/suite.json --gateway-news`, write a TOML config for `TrafficConfig` in `packages/distillation/src/distillation/benchmarks/traffic.py` with your endpoint and credentials, then run `distill traffic run --config CONFIG.toml` and `distill traffic report --path RUN.json`. For the `ag_news` gateway domain, set `generation.max_output_tokens` to the gateway's cap, 256 by default. The authored snippets are wrapped in the news-classification template and are not representative news articles. The report labels actors by the frozen suite and includes decision coverage. This synthetic suite is not a substitute for corpus-based campaign and legitimate-client evaluation.

To evaluate a rolling budget, treat it as a named arm: use a new state file and the same schedule, seed, deadline, and account mapping as the baselines. Count released output from `release` events, not decisions, and count reservations left outstanding as acquired, because their output cannot be excluded. Report refusals by `reason` and `entitlement`, so budget, quota, cap, and detector effects stay separate; an entitlement refusal never counts as detection. `tests/test_crash.py` checks enforcement across a forced crash without a model; it is a software test and says nothing about effectiveness. See [what budgets establish](harness.md#what-budgets-establish).

## Comparison and uncertainty

The matched-attacker-budget view fixes query attempts, output-token budget, money and deadline, then reports acquisition and student outcomes. The matched-legitimate-utility view fixes the metric, target, population and tolerance and checks observed utility before comparing attack cost. `distillation.evaluation_protocol.compare_conditions` checks supplied declarations and observed utility; researchers must verify them against the actual schedules, invoices and outcomes. Match all priority profiles, not merely a pooled mean. Report raw requests, outputs, tokens and distinct examples rather than inventing a universal information score.

Use paired campaigns or source families as independent units and report each unit when there are few. The protocol module supplies a cluster-mean percentile bootstrap and a one-sided zero-event bound. A 95% zero-event bound is `1 - 0.05 ** (1/n)`, approximately `3/n` for independent units. Clopper-Pearson binomial intervals assume independent trials and can be optimistic when accounts share sources; neither generated accounts nor overlapping windows create independent source families. With few clusters bootstrap intervals are unstable. Training seeds measure optimization variability conditional on the data, not independent campaigns. Prespecify primary comparisons and account for multiple tests, or label them exploratory.

## Student plan

`uv run distill student-plan --family FAMILY --seed 1 --cost-per-run 1.0 --output plan.json` writes a plan, not training. Repeat `--family` and `--seed` for the intended family by seed panel. The plan includes the base, gold and undefended-teacher controls, a defended-teacher arm, and checkpoints of 100, 300, 1,000, 3,000, 6,000 and 12,000 examples for supervised controls. Cost is the supplied per-run amount times planned runs; it excludes other costs unless included in the supplied amount. Attach the actual datasets and conditions before execution. Freeze a capability target on development data, then use objective task metrics and held-out source families. Measure cost and time to target, including censoring when the target is not reached.

## Proposed acceptance targets

- Legitimate utility: at most one percentage point loss in correct task completion in each priority group and at most 1% restricted horizons, with uncertainty and independence stated.
- Security economics: at least twice the attacker spend or time to a prespecified capability target, with source-clustered uncertainty excluding no improvement under the strongest declared adaptive attack.
- Incremental mechanism: outperform the strongest matched quota, token and rate baseline at matched legitimate utility; if fewer examples explain the result, claim acquisition control only.
- Accounting: crash, retry, cancellation, duplicate proof, concurrency and horizon rollover preserve the stated release bound. The separate accounting implementation must provide and pass these gates; current event logs cannot establish them.
- Sequential and operational claims: evaluate the exact selection and reset policy, report calibration limits, and measure latency, compute, review and recovery. Do not infer anytime validity from marginal calibration.

These are proposed thresholds for preregistration, not evidence of achieved performance. A fresh, source-disjoint protected run and actual student evaluation are required for effectiveness claims.

### Adaptive collection options

Direct-teacher campaigns can opt into a second endpoint with `gateway collect --policy none --alternative-url URL --alternative-share SHARE`. Both endpoints use the same campaign HTTP allowance, including proof submissions and failures. This option is restricted to direct-teacher campaigns because bypassing a protected gateway would invalidate its policy comparison. The assignment uses offline CPU hashing and does not call either teacher during scheduling.

Optional fixed schedules accept `--paraphrase` for deterministic CPU phrase substitutions, `--user-prefix` for an instruction before each user message, and `--assistant-prefill` for an assistant continuation where the endpoint supports it. The phrase rewriter is deliberately limited and does not perform back-translation. The Python transform interface accepts another identified rewriter. `--human-bursts` adds seeded sessions and long idle gaps to fixed schedules; it cannot be combined with online selection or rotation. These options and rewriter identity are frozen in the inventory and execution contract. A transformed schedule still spends one shared HTTP attempt per submission, including proof redemption.

The inventory and contract record the file digest and selected request IDs.

It asks for a JSON array of answer strings, retains each member in the inventory, and keeps the output cap at the smallest member cap. One HTTP submission is charged for the batch and each parsed answer enters the ledger with its original example ID. The request's token usage is recorded once, on the first member; other members have unknown usage. Malformed arrays are dropped or retried as a whole. Batching currently requires a fixed schedule and cannot be combined with verifier filtering, assistant prefill, session replay, or account rotation. An endpoint may not follow the JSON format, and caps can truncate a multi-item answer.

The scorer identity and threshold are recorded in the contract; scores below the threshold are dropped or retried under the same HTTP allowance. The operator must pin the scorer code and account for its offline compute. A scorer must not make unaccounted online calls. Confidence scoring cannot be combined with batching.


Inputs are gateway schedule lines, campaign ledger lines (one principal in file order) or gateway BenignRequest lines. `--benign` repeats and pools roles. Without `--embeddings`, the pinned BGE encoder embeds each distinct detector text once; the cache format is the one `shadow-check --embeddings` reads. `--calibration` supplies the existing pooled MMD as the baseline and requires the calibration's window size; without it, the baseline uses 20 training-split benign windows as references with a median bandwidth. Topic cells come from seeded k-means (`--topic-cells`, default 8) on `--topic-fitting`, or on the benign inputs when that is omitted. The output directory receives `report.json` and `summary.md` and must be new or empty.

A window is `--window-size` consecutive requests from one account (default 100, the deployed window). Every window is one sample. Content sources are `corpus:<--source-key>` (default `group_id`, so SQuAD questions about one article share a source). Benign windows are also connected through their account. An attack schedule is one principal, so its prompts are first divided into two source-disjoint pools, which become separate components. `split_windows` then assigns connected components to train and test. It keeps at least two windows of each class per side and prefers the assignment whose worse class is closest to the requested test fraction. Each attack runs in schedule order and topic-sorted order (`--order`), using the `evidence-check --reorder topic` sort key with the original time slots.

Controls rebuild attack windows from that split's attack prompts, so source disjointness is preserved and checked. Each built window copies one benign window from the same split: `domain` copies the per-position domain, `topic` the per-position (domain, topic cell), `size` the repeat structure and so the distinct-prompt count, `client` the timestamps, and `all` combines them. Prompts are drawn in pool order, so a topic-sorted pool produces topic-concentrated windows. A benign window whose requirements the remaining pool cannot meet is dropped, so matched counts shrink; they are reported per control.

Tests are fitted on training windows and evaluated once on test windows:

- `c2st_logistic` and `c2st_mlp`: classifier two-sample tests on the window mean embedding plus within-window dispersion. The logistic ridge is selected on an inner source-disjoint split of the training windows; the MLP uses one tanh layer on 16 training-split principal components.
- `learned_mmd`: a Gaussian kernel whose bandwidth multiple and feature weighting (uniform or training-split mean differences) maximize the training statistic's permutation z-score, then a held-out MMD permutation test. Its AUC uses the training witness.
- `pooled_mmd_baseline`: the existing window score, with its direction chosen on training windows.
- `volume_session`: distinct share, prompt-length moments, domain count and entropy, and inter-arrival gap and duration statistics. Client labels, profiles, output caps and identifiers are excluded. Generator timestamps make timing features separate trivially unless the `client` control is applied.

Each test reports held-out AUC, a 95% percentile interval from a bootstrap that resamples source groups within each class, and a permutation p-value over test labels with fixed predictions (the learned MMD uses its MMD statistic). The interval is undefined, never replaced by a window-level interval, when a class has fewer than two test groups. Window-level permutation treats windows as exchangeable and can be optimistic when windows share sources. `retained` is the fraction of the unbalanced AUC above 0.5 that remains under a control.

The decision rule is fixed in code. A comparison survives when, under `all`, a semantic test (the two C2STs or learned MMD) has p below 0.05/3 and an interval that does not include 0.5. An undefined interval does not veto survival. Source corpus is not a matching factor. The report gives the share of attack prompts whose (domain, corpus) pair appears in the benign inputs. A comparison is marked inadequate when that share is below one half (`corpus not balanceable`), when the smaller matched test class has fewer than 20 windows, or when a semantic interval is undefined; an inadequate disappearance reflects low power and is not a stop signal by itself. An attacker can reorder prompts without extra queries, so an attack survives only if every tested order survives. The overall line is `separation survives balancing` if any attack survives and `separation disappears after balancing` otherwise. The summary names the attacks that drive the line and gives each test's `retained` share per control.

The source-connected grouping is `harness.separation_groups.connected_source_groups`: windows sharing any source identifier, including transitive overlaps, stay together. The helper reports an error when its seeded search finds no usable assignment.

## Cached output defenses and matched quota comparison

`distill output-study` prepares output-transform datasets from one cached acquisition and compares supplied student evidence. It compares output defenses with quotas, not detector admissions, and cannot establish a detector-versus-quota result. It does not run a teacher, train a student, optimize a prompt or produce effectiveness measurements. Its tests use CPU fixtures and the fake teacher. Preserve frozen ledgers, acquisition manifests and existing run directories. Output files are exclusively created and never overwritten.

The named serving baseline is `quota_tokens`, selected with `HARNESS_POLICY=quota_tokens` and declared to collection with `distill gateway collect --policy quota_tokens`. Configure `HARNESS_OUTPUT_TOKEN_BUDGET`, `HARNESS_STATE_DB` and optionally `HARNESS_REQUEST_QUOTA`; see [quota serving configuration](harness.md#named-request-plus-token-quota). Use fresh database files per setting. Query-only offline replay cannot enforce token reservations and does not support this arm.

### Search development utility measurements

Measure task-success loss relative to allow for the candidate and a grid of request quotas and request-plus-token quotas on the same development population and schedule. Declare every stratum before searching, including specialists and batch users. Supply a JSON file with this structure; numbers below illustrate an input schema, not experimental results:

```json
{
	"split": "development",
	"population_id": "declared-population-and-version",
	"schedule_sha256": "sha256-of-development-schedule",
	"tolerance": 0.01,
	"candidate": {
		"arm": "dense_locked",
		"loss_by_stratum": {"casual": 0.02, "specialist": 0.05}
	},
	"settings": [
		{
			"policy": "quota",
			"request_quota": 100,
			"loss_by_stratum": {"casual": 0.02, "specialist": 0.05}
		},
		{
			"policy": "quota_tokens",
			"request_quota": 100,
			"output_token_budget": 20000,
			"loss_by_stratum": {"casual": 0.02, "specialist": 0.05}
		}

```

Run `uv run distill baseline match-quotas --development DEVELOPMENT.json --output MATCHES.json`; this study adds no second matcher. One setting must match the candidate within the absolute probability-loss tolerance in every stratum. The search minimizes the worst stratum difference, breaking ties by the setting hash. It records every observed setting and each stratum's match status. Missing strata or an empty matching grid return `not matched`; it never interpolates or assembles a quota from different strata. Measurement collection, sampling uncertainty in utility estimates and held-out confirmation remain the experimenter's responsibility. A declared development label is not proof of source separation.

### Build output and adaptive datasets

Start with one `distill acquisition manifest --response-policy clean` cache and require its ledgers on disk. `distill output-study build --manifest CACHE.json --recipe RECIPE.json --adapter project_adapter:factory --output ARM.json` verifies the manifest, ledger and record hashes and uses accepted training rows. Fresh collection writes pending responses, so pass `--include-pending` to build from them; the artifact records the choice and rejected rows never enter. A manifest with no eligible rows is refused rather than producing an empty arm. The trusted Python factory returns `distillation.output_sets.Adapters` with an exact token codec, a task-specific answer extractor that returns a releasable form such as `#### 42` and returns it unchanged when reapplied, a task-validity checker, frozen identities for those components and an optional rewriter callback. No approximate whitespace tokenizer is supplied for experiments. The rewriter receives the cached draft and instruction and returns `Rewrite(text, queries, money, seconds)`. Return an empty text with the actual cost after an unsuccessful call, or abort the build on an exception; exceptions never trigger an unaccounted clean-draft release. Identify the teacher and rewriter model revisions in the adapter identity, reuse the loaded teacher for the default defense and declare any larger rewriter as a separate resource condition.

A recipe is a JSON serialization of `output_sets.Recipe`, for example `{"arm":"dense_locked","fallback":"withhold","loss":"ordinary"}`. Supported output recipes are `clean`, `compact_verified`, `final_answer_only`, `paraphrase` and `dense_locked`. The dense recipe stores the exact dehyphenated Appendix A.2 instruction and the SHA-256 of the arXiv 2602.15143v2 PDF, kept on the `archive` branch as `research/papers/PAPER_DEFENSE_Trace_Rewriting_2602.15143v2.pdf`. Appendix E.3 discusses rewriter/teacher sizes and provides no additional instruction. The answer-locked recipe rejects a changed or unextractable final answer, a task-invalid rewrite, and a defense rewrite identical to the clean draft. It is the stricter variant, not a claim to reproduce the paper's unconstrained condition. Compact and paraphrase instructions are repository controls, not attributed to the paper. A paper-style unconstrained arm and prompt optimization are outside this builder. The [gateway output policy](harness.md#opt-in-output-policy) sends the rewriter only the explanation, attaches the locked answer itself and refuses near copies by word 5-gram overlap. This builder passes the whole draft to the adapter and refuses copies through the shared `copied_fraction` check. Cached-arm student results do not describe gateway output unless the adapter splits the draft at `####` the same way.

Choose `fallback` explicitly as `withhold` or `final_answer`. A final-answer fallback releases only the extracted clean answer if the task validator accepts it; otherwise it withholds, and the row records `withhold`. Every row records the failure, fallback, answer equality, task-validity check, released tokens, training tokens, hashes and rewrite queries/money/time. Withheld rows have no SFT example and still consume an acquisition query. The builder never silently releases the original clean explanation after a failed rewrite. Task checks are adapter assertions, not independent measurements of explanation usefulness or legitimate-user utility; measure those separately.

Adaptive recipes are `final_answer_extraction`, `cleaned_explanations`, `paraphrased_protected` and `protected_loss`. Pass the full protected output artifact with `--protected ARM.json`; it must derive from the same acquisition manifest. They train only from protected text, never replenish a withheld response from the clean cache, and retain the original protected output's released-token charge when they discard tokens. `protected_loss` requires `"loss":"filter"` or `"loss":"clip"` and a positive `loss_threshold`. `loss_values` specifies the per-token objective, and `tensor_loss` is a differentiable trainer hook for unmasked completion-token losses before reduction. Filtering zeros gradients above the threshold while retaining the original denominator; clipping caps token loss and its gradient. The generic learning-curve runner does not automatically install this hook: a training adapter must apply the frozen recipe and record it with the student artifact. An optimizer-step match alone does not equalize supervision.

Quota training arms use recipe names `quota` and `quota_tokens` and require `--admissions ADMISSIONS.json`. This file declares `manifest_digest`, `policy`, `settings` containing `request_quota` and, for `quota_tokens`, `output_token_budget`, `accepted_example_ids`, `evidence_path` and `evidence_sha256`. Run the gate on the fixed stream and freeze its observed admitted IDs; the builder verifies the evidence file hash, preserves refused queries as withheld rows and joins accepted outputs to the one acquisition cache. The accepted-ID declaration is an operator assertion; a hash does not independently prove that an arbitrary evidence file supports it. Do not use a request-only replay as evidence of token enforcement.

Clean control recipes are `clean_matched_queries`, `clean_matched_tokens`, `clean_truncated` and `clean_subsampled`. The first two preserve full clean responses and select by the corresponding candidate budget. `clean_truncated` requires positive `max_tokens` and truncates with the frozen codec; its validity and answer loss remain visible. `clean_subsampled` preserves full responses and uses an explicitly reduced query budget, rather than silently truncating them. All share cached prompt identities and hashes.

For every arm run `uv run distill output-study select --arm ARM.json --by queries --budget N --seed 42 --output QUERIES.json` and a separate selection with `--by tokens --budget T --output TOKENS.json`. The existing acquisition selector supplies the nested seeded ordering and prefix rule, with token counts replaced by exact released counts. Whole responses are retained; token slack and cache exhaustion are reported. Short output can select more distinct examples from this cache, but it makes no new calls. If the cache cannot fill the budget, acquire additional distinct examples under a new frozen manifest and rebuild every arm. Train on non-null `rows[].sft`; retain the complete artifact and its digest for the student report. Reuse `learning_curve_runner.render_rows` for chat-template and length checks, and the frozen learning-curve recipes for training parameters. These dataset files are not complete learning-curve plans.

### Join students and require both budget views

Run `uv run distill output-study comparison-report --declaration COMPARISON.json --gate-report CLEAN_GATE.json --output REPORT.json`. Pass the report written by `distill baseline clean`. A candidate must use a protective output recipe, not `clean`. It must be intact, have passed and name this acquisition manifest in `manifest_digest`; an absent, failed, edited or unrelated gate refuses a verdict.

The comparison declaration contains `development` with the complete measured search input above, `manifest_digest`, `evidence_kind` set to `measurement` for real observations or `fixture` for development fixtures, at least three distinct `seeds`, `adaptive_arms` listing every declared adaptive attacker, `reference_queries`, `capacity_evidence` and `benign_schedule` paths, `utility_baseline` naming the results `index` path, `run_id` and `arm` of the baseline utility run, which must be valid under [the utility validity rule](#acquisition-manifests-math-curves-and-clean-baseline-gates), and both `views.equal_query` and `views.equal_token`. Each view maps the candidate label, `quota`, `quota_tokens`, every adaptive label and all four clean control labels to entries of this form:

```json
{
	"training_set": "path/to/frozen-selected-set.json",
	"students": {"42": "path/to/seed42.json", "43": "path/to/seed43.json", "44": "path/to/seed44.json"},
	"short_output_cost": {"extra_queries": 0, "money": 0, "seconds": 0}
}
```

Each student file wraps one existing `transfer_metrics.transfer_report` result as `{"seed":42,"training_set_digest":"SELECTED_SET_DIGEST","gate_report_sha256":"GATE_FILE_HASH","transfer":{...}}`. Preserve task-family pairing in teacher/base/clean/defended correctness arrays before computing transfer; use paired task-family resampling from `transfer_metrics`. The report verifies the seed, selected-set digest, clean-gate dependency and usable transfer denominators. It records each student's file hash and full transfer result. A missing student, undefined interval or mismatched join returns `no result` for that arm. Quota datasets must bind the selected development setting, and adaptive datasets must reference the candidate's full output artifact.

Record observed extra acquisition queries, incremental acquisition money and elapsed seconds for the short-output attacker, including explicit zeros when appropriate. `extra_queries` must equal selected distinct queries above `reference_queries`. These costs exclude separately recorded offline rewriting/training costs; declare expanded attacker compute as another condition. Both views require equal declared budgets and equal actual query counts or released-token totals for the main panel. Reduced truncated/subsampled controls are reported separately. Discrete token slack can prevent a verdict; adjust declared budgets or use an explicitly truncated control, rather than pretending unmatched token totals are equal.

The report reuses `compare_conditions` separately for every legitimate stratum and requires the existing capacity preflight for the declared benign schedule, whose hash must equal the measured development schedule. At every paired training seed, it takes the largest transfer upper bound over the candidate and all declared adaptive variants. That bound must be strictly below the lower bound of both matched quota baselines in both budget views. This conservative interval-separation rule leaves uncertainty per seed; it does not invent a joint seed interval. One seed is screening only. Missing arms, missing gate or capacity evidence, unmatched utility, incomplete budgets or fixture evidence always yield `no result`. Declaring an attack panel does not establish that it contains every affordable attack, and CPU fixture success cannot establish a protective effect.
