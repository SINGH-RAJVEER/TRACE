## Agreed task-only scope

## Manuscript discrepancies found against the repository (2026-10-16)

These come from comparing `paper/main.tex` with the merged harness, `just paper-tasks`, and `just start`. Repository-side fixes are listed under [repository audit findings](paper-tasks.md#repository-audit-findings-2026-10-16).

- [ ] High priority: state what makes extraction traffic distinguishable. The attacker pool and the legitimate pools are hash-split halves of the same training split, so a pure extractor that samples the task uniformly should match the benign references in expectation, and the policy would escalate it at about the benign rate. With realistic specialist clients, the benign accounts deviate and the broad attacker does not. Either define the signal (coverage breadth relative to an account's own history, task-matched specialist references, mixtures) or reframe RQ2 so quota and rate baselines are the fair comparison and MMD is tested only where a shift exists. Confirm with one `harness replay` of a budget's prompts as a single account before deciding.
- [ ] Declare or remove the L4 noise arm. Table I and Section II-C say L4 refuses and served answers stay unchanged, but `harness-api` and `harness replay` default to keyed noise at L4. If kept, add it as a separately reported arm with its watermark test, and count silently corrupted benign responses inside unconditional utility.
- [ ] Declare or drop the extra accumulators. The harness also implements `e_process` and `e_cusum` with Ville thresholds, which the paper does not mention. Either list them as secondary variants or keep them out of every reported table.
- [ ] Retitle the paper. "Session-Level Behavioural Profiling" and "Semantic Embeddings" promise more than the account-level accumulated MMD evidence Section III specifies; rate features are only a baseline.
- [ ] Disclose the supported reference-window count per task. Section III-B fixes 20 reference windows of 100, but the GSM8K fitting pool supports about 13, and `just start` lowers the count silently.
- [ ] State whether the aggregate monitor runs. At 1,500-request windows and 20 references it needs 30,000 fitting requests; the AG News (about 21,600) and SQuAD (about 15,800) fitting pools are smaller, so calibration skips it and Table VII's aggregate-alert column cannot be filled. Reduce aggregate references, or move aggregate alerts out of scope.
- [ ] Reconcile training-recipe selection. Section IV-B selects the learning rate from {1e-4, 2e-4} and epochs from {1, 2, 3} on development data; the repository fixes 2e-4 and 3 epochs with no sweep. Run the sweep or state the fixed recipe.
- [ ] Remove or mark as not run every table row the repository cannot produce: the Table III reproduction rows (item 19), WildChat and LMSYS in Table II and the benign robustness table (item 17), the stride and direct-block ablations (item 22), the active and benign-matched adaptive schedules (items 13 and 14), and the optional privacy extension in Section IV-I.
