## Which decoder interfaces and dependencies can TRACE actually use?

### Takeaway

TRACE currently controls generation parameters over HTTP, not logits. The best first feasibility probe is the native Gumbel watermark in the inspected vLLM `v0.31.0` source, followed by a keyed KGW implementation if per-tenant keys or bias control are required. Neither is a verified drop-in on this checkout. SynthID Text is available in HF generation but remains explicitly unimplemented in the inspected native vLLM watermark documentation. ### Inferences

- Start with the native sampler to establish whether this model and serving runtime can embed and detect a watermark at all. Pin the full serving environment independently. A successful native shared-key probe does not satisfy per-tenant keyed KGW or SynthID compatibility.
- For keyed KGW, use a separate Python 3.12 plugin package, a trusted adapter extension and a matching detector. Keep model imports and serving dependencies outside the Python 3.14 web app. The current app package's Python requirement prevents simply installing the whole TRACE workspace into Python 3.12.
- Metadata tags, HTTP headers, signed receipts or appended provenance fields record a response; they do not bias generated token choices and disappear when text alone is copied. A prompt requesting a signature or rewrite changes prompt behavior without implementing a keyed sampler. Static OpenAI `logit_bias` cannot express context-dependent per-token KGW across a response. Repeated one-token HTTP requests would change chat templating, latency and context semantics.
- Preserve the current default and historical study output when the feature is disabled. Opt-in sampling at nonzero temperature requires a separately named experimental profile, because changing TRACE's default greedy behavior changes the baseline.

## Which watermark family is the best implementation candidate?

### Takeaway

Use native Gumbel for the smallest serving feasibility experiment and keyed soft KGW for the first custom controlled comparison. Keep HF SynthID as a reference/fallback experiment. Distribution preservation is an ensemble property under specific assumptions; it does not promise identical answers, correctness on every task, or successful detection on short constrained outputs. [Distortion-free paper](https://arxiv.org/abs/2307.15593), [KGW paper](https://arxiv.org/abs/2301.10226).

### Cited findings

- KGW chooses a context/key-dependent green token subset and adds a positive logit bias before token selection. Detection tests excess green tokens; the authors supply generation and detection code. HF provides `WatermarkingConfig`, `WatermarkLogitsProcessor` and `WatermarkDetector`. Its fixed demonstration hashing key is not a deployment secret. [KGW paper](https://arxiv.org/abs/2301.10226), [author code](https://github.com/jwkirchenbauer/lm-watermarking), [HF pinned processor](https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/generation/logits_process.py), [HF pinned detectors](https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/generation/watermarking.py).
- Soft KGW can change an argmax and HF demonstrates greedy watermarked generation. A vLLM V1 implementation must declare `is_argmax_invariant=False`; otherwise the engine can skip it on all-greedy batches. This does not supply entropy where only one acceptable answer exists. [HF processor example](https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/generation/logits_process.py), [V1 guide](https://github.com/vllm-project/vllm/blob/v0.22.0/docs/features/custom_logitsprocs.md).
- HF SynthID uses a keyed g-function and n-gram state, with repetition handling. Google's integration describes use after top-k/top-p and generation through `watermarking_config=SynthIDTextWatermarkingConfig(...)`; a Bayesian detector requires training data. This is HF generation support, not vLLM support. [Google integration documentation](https://ai.google.dev/responsible/docs/safeguards/synthid), [HF implementation](https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/generation/logits_process.py), [HF detector implementation](https://github.com/huggingface/transformers/blob/v5.19.0/src/transformers/generation/watermarking.py).
- DeepMind's current reference repository describes Gemma/GPT-2 mixins, a training-free frequentist detector and a trained Bayesian detector; it says its reference subclasses are not intended for production. Its current Threefry randomness is not a vetted cryptographic primitive. Its 0.3.0 metadata requires Python >=3.11, Transformers >=5.16,<6, Torch >=2.5 and JAX/Flax/Optax dependencies. This differs from treating old HF examples as the complete current stack. [Reference repository](https://github.com/google-deepmind/synthid-text), [dependency metadata](https://github.com/google-deepmind/synthid-text/blob/main/pyproject.toml).
- The October 2026 SynthID tournament document supplies engine-oriented pseudocode, dual-key speculative sampling and detector/testing guidance. That is a porting specification, not an official Qwen vLLM SynthID plugin. [Tournament specification](https://github.com/google-deepmind/synthid-text/blob/main/docs/tournament.md).
- Kuditipudi et al. use inverse-transform or exponential-minimum sampling with a keyed random sequence and alignment detection. Their low-entropy instruction experiment detects substantially fewer samples than their higher-entropy model experiments. Their distortion-free result is qualified by a finite generation budget and random-key assumptions. [Paper](https://arxiv.org/abs/2307.15593).
- SemStamp hashes sentence embeddings and rejects candidate sentences until they occupy acceptable semantic partitions. It therefore requires sentence candidate generation, embedding and rejection control rather than a simple token processor. [Author paper](https://arxiv.org/abs/2310.03991).

### Inferences

| Candidate | Decoder work for TRACE | Main reason to try or defer |
| --- | --- | --- |
| Native vLLM Gumbel | Separate pinned v0.31.0 environment and native sampler configuration | Lowest custom generation code; shared engine key, nonzero temperature and noncryptographic PRF limit scope |
| Keyed soft KGW | MRV2-specific batch processor, trusted key selector, matching detector | Simple bias-strength sweep and interpretable statistics; quality changes and plugin maintenance are real costs |
| HF SynthID Text | Separate HF generation backend or carefully tested vLLM sampler port | Existing HF processor; detector calibration and state/truncation order must match; no native SynthID in inspected vLLM tag |
| Kuditipudi distortion-free sampler | Replace/control sampling randomness and preserve key alignment | Useful research comparator; more invasive than logit bias and no established TRACE integration |
| SemStamp | Sentence rejection loop plus embedding model | Consider only for prose; additional generation cost, buffering and poor fit for JSON/code or immediate streaming |

- For KGW, begin with a documented algorithm profile using gamma 0.25, bias candidates 0.5/1/2, and context widths 1/2/4. These are experimental sweep choices, not selected production settings. Exact HF RNG/permutation replication is required to claim HF detector compatibility; a GPU hash-threshold green set is a distinct version even if mathematically KGW-like.
- A keyed PRF such as HMAC can supply a stronger technical key boundary than a default seeded PRNG, but a cryptographic per-candidate implementation needs its own throughput and statistical tests. Do not quietly label the HF hashing scheme or vLLM Philox cryptographically secure. Preserve reference compatibility first with nonsecret fixture keys; version any stronger design separately.
- HF Qwen text generation with the pinned tokenizer/model revision and explicit watermark config is the honest fallback if a qualified vLLM release cannot run the model/plugin combination. Benchmark its serving latency separately. An HF class import alone does not validate Qwen execution.
- JSON syntax masks must remain hard masks. Additive KGW must preserve negative infinity and never revive forbidden tokens. Grammar-forced tokens offer no useful choice. Deterministic code or exact JSON bytes cannot both remain unchanged and carry a new token-choice watermark in general. A supported policy can abstain on these outputs and report reduced coverage.
- Code, numerical answers and short labels are high-priority utility risks. Measure executable pass@1, numeric exact match, schema validity and answer agreement, rather than assuming prose-quality results transfer. Watermarking code comments alone is easy to strip and leaves comment-free answers uncovered.

### Gaps

- No latency, GPU memory, task accuracy, best bias or detection sample length has been measured for this Qwen revision. There is no evidence here that one family dominates all TRACE tasks.
- Per-tenant keys within one native vLLM engine are not provided by the inspected config. Separate key-bound engines are a costly experimental alternative; a custom processor/sampler is required for efficient shared-engine key selection.
- No proof was found that an unmodified HF SynthID processor can be transplanted into the vLLM custom-processor position while preserving its intended truncation order, state and distributional claims.

## How should a first prototype be evaluated and its evidence preserved?

### Takeaway

Separate interface feasibility, teacher utility, direct-output detection and student inheritance into distinct gates. A detected statistical pattern supports only a calibrated statement about that profile and sample; it does not prevent extraction or universally prove authorship. [Radioactivity study](https://arxiv.org/abs/2402.14904), [watermark stealing](https://arxiv.org/abs/2402.19361), [removal limits](https://arxiv.org/abs/2311.04378).

### Cited findings

- vLLM warns that a seed alone does not ensure reproducibility. Its guidance requires deterministic offline scheduling or batch invariance; online runs require batch invariance, with guarantees still limited to the same hardware and vLLM version. [Official reproducibility guidance](https://docs.vllm.ai/en/latest/usage/reproducibility/).
- The legacy V1 sampler applies non-argmax-invariant processors before greedy selection and temperature, then argmax-invariant processors and top-k/top-p for stochastic sampling. A bias before temperature has a temperature-dependent effective strength. Treat runner/version and processor order as algorithm metadata. [Sampler code](https://github.com/vllm-project/vllm/blob/main/vllm/v1/sample/sampler.py).
- The reliability paper reports robustness conditional on sufficient surviving text, including much longer samples after strong paraphrasing. Its results are not a universal short-output guarantee. [Reliability paper](https://arxiv.org/abs/2306.04634).
- Watermark stealing can enable both spoofing and removal from API observations; a secret detector is not a proof against this. [Attack paper](https://arxiv.org/abs/2402.19361).
- The strong-watermark impossibility result assumes a quality oracle and an efficiently mixing perturbation process; it is a qualified theoretical result with empirical attacks, not a claim that every watermark always fails. [Paper](https://arxiv.org/abs/2311.04378).
- Watermark radioactivity can survive fine-tuning, depending on watermark strength, training proportion and training process. Its open-weight and black-box tests have different access and statistical assumptions. [Full author paper](https://arxiv.org/html/2402.14904v2). Distillation has also been studied as a way to replicate a watermark and spoof a source signal. [DITTO paper](https://arxiv.org/abs/2510.10987).

### Inferences

1. Freeze the serving lock, wheel/source hashes, runner, device/driver, tokenizer files/revision, vocabulary and special-token IDs, model revision, template hash, thinking flag, generation defaults, code digest, key ID and algorithm version before measurements. Capture actual generation config, not just fields sent by TRACE.
2. Start without speculative decoding. Use nonsecret fixture keys for CPU score vectors and synthetic logits. Test mixed enabled/disabled requests, tenant separation, cancellation, slot reuse, reorder, preemption/resume and retry. Require identical detector green sets/g-values across generation and detection. For native Gumbel test PRF compatibility vectors. Disabled mode must preserve payload and outputs under the same runtime.
3. Streaming must watermark before each sample and keep state for the logical request, independent of SSE chunks. TRACE currently buffers whole responses; any future streaming API needs its own contract. Do not flush sentence-level semantic candidates before acceptance. Detector state cannot treat partial text deltas as independent samples.
4. Evaluate paired control/marked prompts on frozen source-disjoint calibration/development/test splits across AG News, SQuAD, GSM8K, code and a new JSON/low-entropy stress panel. Preserve existing readings unchanged. Compare identical seeds but do not assume identical random draws between algorithms. Sweep temperature 0/0.7/1, lengths 16/32/64/128/256/512/1024 and concurrency 1/4/16. Add enough independent seeds and prompts to estimate uncertainty; these are planned cells, not evidence.
5. For KGW record green count G, effective unique scored contexts T, gamma and `z=(G-gamma*T)/sqrt(T*gamma*(1-gamma))`. Exclude prompt/padding/special tokens by a frozen rule. Repeated n-grams invalidate naive independent-token counting; score each eligible context/token event according to the detector contract. Retokenization of decoded text can differ from served IDs. Test both exact IDs and text-only recovery with fixed normalization, no cleanup, and recorded prompt-context policy.
6. Use held-out unwatermarked task text, wrong keys, ordinary human/reference text and alternate-model generations as null controls. Calibrate by task, length, profile and key, with separate final tests. A p-value is not a posterior probability of model origin. Correct for trying many keys, versions, windows and tenants; calibrate the maximum statistic for sliding-window scans. Never concatenate documents as if the boundary were a generated n-gram.
7. Choose an initial direct-detection target such as familywise false-positive probability <=1e-3 and report TPR, FPR, confidence intervals and abstention coverage. This is a proposed experiment target. Zero false positives in n independent null documents has a roughly 3/n upper 95% bound; supporting 1e-5 would require roughly 300,000 independent null cases, before multiplicity. Short/low-entropy samples should return `insufficient_evidence`, not a confident negative. Determine a minimum effective sample length empirically.
8. Measure p50/p95 TTFT, inter-token latency, end-to-end latency, tokens/s, memory, CPU/GPU synchronization cost and completion rate at matched offered load. Compare greedy original, stochastic unwatermarked and stochastic marked separately. A GPU-friendly O(batch*vocabulary) hash/bias operation can still be expensive at Qwen vocabulary sizes; repeated CPU permutations or full logits transfers are unacceptable without measurement.
9. Attack tests should cover truncation, copy/paste into unrelated text, formatting/Unicode normalization, code comment stripping, identifier renaming, paraphrase, translation and quality-preserving iterative rewriting. Record attack query/compute budgets and retained task correctness. Evaluate spoofing and cross-tenant confusion with wrong keys. No attack models or APIs were invoked for these notes.
10. Treat student inheritance as a later independent study. Train matched students on unmarked and marked targets with identical budgets, include data-mixture and fine-tuning sweeps, test disjoint prompts, and separate white-box logit scoring from black-box generated-output scoring. A strong teacher detector does not establish inherited student signal, and inherited signal can also enable spoofing. Report student capability separately from detection.

### Gaps

- No prototype or evaluation command below has been executed. Commands for proposed modules are specifications for future work, not existing TRACE CLI commands. No empirical watermark or anti-distillation effectiveness claim is justified.
- Key lifecycle design still needs implementation tests. Proposed technical contract: server derives tenant/version/epoch keys under domain separation from a protected root, exposes only an opaque key ID to the adapter, pins the resolved key version for request/retry/detection, and retains retired detector keys for old artifacts. Do not reuse bearer tokens as watermark keys, accept caller-selected keys or dump keys into manifests/logs/process arguments. Native 64-bit keys impose a format limit; root-key strength does not make Philox cryptographic.
- Native shared-key vLLM cannot be reported as tenant attribution. The current endpoint lacks the trusted tenant identity needed to choose a key. Historical detection needs retained tokenizer, template, algorithm and key-version records; rotation without those records makes old evidence unverifiable.
