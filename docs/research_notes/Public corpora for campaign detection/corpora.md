# Public corpora for campaign detection

## Which public corpora can supply realistic baseline traffic?

### Takeaway

Use WildChat-4.8M for observed human chat, OpenHands Feedback for a small sample of actual coding-assistant sessions, and HELM for documented research batch workloads. Add generated SWE trajectories as a separate agent stress-test population. These are candidate baseline sources, not certified benign accounts. Assessment date: 2026-11-05. Only public cards, papers, repository metadata, and local source files were inspected; no dataset shards, gated access, or teacher calls were requested.

### Inferences

Ranked acquisition plan, with no access request or download performed here:

1. Start with open WildChat-4.8M and OpenHands Feedback as separate observed-usage cohorts. Their complementary provenance matters more than pooling their sizes. WildChat supports longitudinal proxies; OpenHands supports actual agent event sequences. Measure usable independent groups before choosing detector window sizes.
2. Add a small versioned HELM suite for researcher batch work and Nebius SWE-rebench for generated agent execution. Retain all outcomes and disclose research/training provenance. These answer whether TRACE penalizes legitimate workload shapes; they cannot estimate production false-positive rates.
3. Inspect only ShareLM's original plugin subset for a second repeated-user cohort, and PRISM for a participant-controlled sensitivity analysis. Verify metadata coverage and session depth before promising enough 100-request accounts.
4. Seek Arena access if historical anonymous-user timing is valuable. Add ShareChat for provider/interface robustness. Chat-1M is lower priority for campaign detection because its published release loses account/timing structure.
5. Keep SWE-smith and OASST2 as separately named controls. Avoid treating convenience SFT mixtures, ShareGPT reuploads, or synthetic instruction sets as independent user traffic. For example, the [original UltraChat paper](https://arxiv.org/abs/2305.14233) explicitly describes generation without human queries.

### Gaps

- No reviewed corpus provides verified billing organizations/API keys, account age, trust decisions, purchase/appeal history, complete retries, API throttling, or consented evidence that output was not used for extraction. Authenticated production telemetry remains missing.
- Independent proxy accounts are not established by a row count. NAT/shared IPs, changing IPs and selective sharing can merge or fragment users. Neither public release nor non-toxic content certifies legitimate intent.
- No representative distribution of enterprise batches, researcher automation and deployed agents was found. The reviewed 2026 [longitudinal comparison](https://arxiv.org/abs/2605.29018) specifically finds WildChat skew toward proficient power users. Treat this as a sampling limitation, not a reason to discard it.
- Gated license agreements and raw files were not bypassed. Chat-1M agreement text was inspected on the public card; restricted file endpoints rejected anonymous access. SWE-Gym sampled rights remain unresolved. HELM needs a selected immutable suite/run manifest and its underlying rights audit before ingestion.

## Which confounds and splits would make the evidence credible?

### Takeaway

Compare traffic intent within matched source populations wherever possible. A detector that separates benchmark wrappers, chat prose and tool transcripts may only identify corpus provenance. Use observed, proxy-timed and simulated cohorts separately; report uncertainty at the strongest defensible grouping unit.

### Cited findings

- Chat-1M explicitly warns of benchmark contamination; WildChat reserves material for WildBench, and ShareLM imports WildChat/PRISM. These sources cannot be assumed independent of each other or of benchmark evaluation prompts. [Chat-1M](https://huggingface.co/datasets/lmsys/lmsys-chat-1m), [WildChat schema/card](https://huggingface.co/datasets/allenai/WildChat-4.8M/raw/main/README.md), [ShareLM](https://huggingface.co/datasets/shachardon/ShareLM)
- Arena exposes paired completions; PRISM exposes multiple model candidates and selected continuations. Flattening response alternatives duplicates prompts and can leak the same decision across train/test. [Arena](https://huggingface.co/datasets/lmsys/chatbot_arena_conversations), [PRISM](https://huggingface.co/datasets/HannahRoseKirk/prism-alignment)
- Generated SWE runs reuse issues and repositories, with explicit training objectives. The correlation unit is larger than a turn or rollout. [Nebius SWE-agent](https://huggingface.co/datasets/nebius/SWE-agent-trajectories), [SWE-Gym workflow](https://github.com/SWE-Gym/SWE-Gym/blob/main/docs/OpenHands.md)

### Inferences

- Build a lineage graph before role assignment. Link shared participant/proxy-account, conversation and branches, repeated request IDs, exact content, near-duplicate prefixes, issue/document ancestry, repository and mirrored source releases. Assign whole connected components; publish how many groups and accounts survive. For generated coding data, report both issue-disjoint and stricter repository-disjoint results.
- Use two distinct split questions. For unseen-principal generalization, hold out entire principals/components and fit topic/normalization parameters only on fitting groups. For drift, train before a fixed UTC cutoff and evaluate later; purge cross-boundary conversations/duplicates and state whether returning principals are allowed. A temporal split alone does not prove principal independence. Sources with missing timestamps cannot supply the temporal test.
- Preserve naturally short sessions and disclose the fraction unable to form a detector window. Do not concatenate unrelated sessions into fabricated “accounts” merely to reach 100 requests. Evaluate window coverage and cold-start behavior separately from full-window restriction rates.
- Stratify source, interface/provider/model, language, domain, prompt length, topic concentration, concurrency/repetition and elapsed-time quality. Report source-conditioned results and a source-prediction control. Match attack and candidate-baseline topic/length/volume and, where available, use authorized same-source attack schedules with disclosed intent instead of assigning all benchmark traffic to attack and all chat traffic to benign.
- Use safety filters only as explicit cohort definitions. Filtering toxic conversations changes population composition and can remove legitimate safety research. Store safety and intent labels separately. Never turn a moderation label or successful patch into an authorization label.
- For timing ablations compare observed event timing, response-completion proxy timing and declared synthetic schedules separately. Keep missingness explicit, never convert dataset order into observed arrival intervals. Synthetic schedules may test robustness to batches or bursts; they cannot validate real account throughput.
- Run privacy screening on a bounded approved sample before importing full text. Keep original identities/URLs/headers in restricted provenance only, use locally pseudonymized grouping IDs, omit demographics from detector inputs, retain deletion lineage, and release aggregate results rather than raw user examples. This is a proposed data-minimization policy, not a claim that de-identification guarantees anonymity.

### Gaps

- A metadata-only audit cannot establish usable account counts, timestamp completeness, long-session coverage, duplicate rates, source overlap or secret-removal recall. Report these as acquisition gates, not achieved statistics.
- Reconstructing teacher requests from a transcript does not reveal suppressed system messages, UI-side tools, failed calls, concurrency, or actual billing organization. Matching these transcripts to TRACE's four task templates would itself change the workload.

## What can TRACE reuse, and what adapter is required?

### Takeaway

The existing source lineage, schedule schemas, connected-component splitting and matched controls are useful. Direct replay of unrestricted conversations or tool trajectories is not currently supported by the controlled gateway. No implementation or frozen artifact was changed for this research.

### Inferences

Proposed adapter, intentionally not implemented:

1. Freeze metadata before text acquisition: repository revision or HELM suite/run manifest, file hashes when acquired, owner/card/license versions, collector version, source lineage, filter policy and allowed purpose. Request only bounded shards after rights/access are settled; do not hydrate `readings/` or reuse historical campaign directories.
2. Normalize to one event per actual model request where reconstructable. Keep `source_id` as release plus stable row/turn/trajectory-event identity, `group_id` as precomputed connected component, `corpus` as original source family, and a sidecar mapping original conversation, participant proxy, repository/issue and duplicate cluster. Dataset-row offsets are fallback provenance, never proof of identity.
3. Preserve user turns and prior context separately. For a user-turn semantic experiment, emit only human-authored current turns and clearly label that scope. For agent-call reconstruction, emit the complete prefix available immediately before each assistant generation, retaining tool schema/calls/results; environment observations labeled `user` in SWE data are not human prompts. Replaying recorded outputs is offline analysis; generating new continuations creates a new workload and must record new timing/model provenance.
4. Record `time_kind` as observed request arrival, observed event, completion proxy, conversation-only, or synthetic; retain missing values in the sidecar. Only assign schedule seconds after selecting a valid replay clock. Exclude proxy/missing timing from arrival-rate claims. Preserve original gaps and simultaneity when available; stable ordering resolves ties without inventing elapsed time.
5. Map tasks only through a reviewed domain classifier/manual audit with an out-of-scope bucket. Keep unrestricted chat and tool work separate from four-task benchmark results. Reuse `PromptSource` and `GatewayRequest` only where their semantics fit; extend strict schemas explicitly when they do not.
6. Assign fitting, calibration, policy-development and locked-test groups before topic fitting or sampling. Keep existing sealed `benign_test` material out of development. Add a chronological split option rather than calling the random component split temporal. Compute and audit connected groups across all releases before generating windows.
7. Start with separate cohorts, not an arbitrary “realistic” mixture: observed chat, observed coding-agent sessions, study participants, evaluation batches, generated agent runs and existing synthetic profiles. Report per-cohort independent groups, excluded/missing events, windows, source-conditioned restriction rates and clustered intervals. Publish mixture-weight sensitivity only when weights are explicit assumptions.
8. A later implementation should extend existing [session tests](../../../tests/test_session_workloads.py), [profile tests](../../../tests/test_profile_workflow.py), [group tests](../../../tests/test_separation_groups.py) and [study tests](../../../tests/test_separation_study.py) for branch/issue leakage, missing clocks, tool-role handling and retained provenance. This documentation-only task required no model runs or test execution.

### Gaps

- Production intent remains the decisive missing label. Public corpora can refute simplistic claims that concentration, repetition or high volume necessarily imply extraction. They cannot establish a deployable false-positive rate against verified legitimate customers.
- Acquisition and implementation have not occurred. “Usable now” means public metadata and an accessible candidate release with a plausible rights path, not a validated local corpus or a completed integration.
